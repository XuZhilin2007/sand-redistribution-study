# v0.5.0 candidate provenance and scope

Prepared 28 October 2026. This guide is new release material; it does not
revise the original mathematical proof, outputs, audit or corrections.

**Identity.** The repository HEAD at consolidation is
`2c337bb4a52a7e79430c6430413893dd79c6e9e4`. The alpha theorem, October 27
corrections and October 28 audit existed as uncommitted/untracked working
files. HEAD alone is not their source identity. The candidate manifest
records exact per-file bytes and origins, plus that distinction. No commit,
Git tag, branch rewrite or release is created by the packaging procedure.

Theorem A's invariants, non-stopping and boundary residence remain analytic
dependencies. The Bernstein and Sturm passes share model/trajectory algebra.
The formal bin-sum check and interval proof share some formulas. These are
useful distinct checks, not proof-assistant verification or human peer review.

**Freeze and reproduction.** The manifest is written after preparation,
before isolated mathematical execution. It enumerates every actual package
file except itself, with SHA-256, size, role and origin. A detached receipt
pins its digest and the deterministic ZIP digest. Hashes generated after a
run cannot replace the preflight inventory or validate evidence that was
overwritten before the check.

Reproduction first checks the exact package file list, file hashes,
historical report/source bindings, stage scope ledger and audited payload
digests. It then creates a new external output directory. The package is
checked again after all stages, including the old evidence. Timing and the
dependent finite-witness runtime hash are the only semantic comparison
exceptions; both old and new witness bindings are separately verified.
Any discrepancy in scientific content fails the run.

The package includes the October 28 audit report and its specifically linked
evidence/programs. Its large duplicate reproduction source tree is omitted;
the linked reproduction reports are retained. The full repository and Git
history remain in the user's workspace. The package is an explicitly
selected verification bundle, not a representation that the entire private
research repository is published.

**Approval boundary.** The candidate is suitable for review only after its
actual ZIP has passed isolated reproduction and preservation checks. A
readiness recommendation is not approval. Tagging and publishing require
the owner's explicit subsequent approval. The preserved audit's mathematical
assessment and the new execution results are stated at their actual levels
of independence.
